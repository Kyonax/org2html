* [v1.2.0] — 2026-09-09
** Changed — every version literal states 1.2.0 (2026-09-11)
- =README.org= (=#+VERSION=, the figlet banner, the shields badge) and both Style Book manifests (=templates/style-book/stylebook.json= for kwo, =templates/style-book/o2h/stylebook.json= for o2h) said 1.1.0 while =package.json= said 1.2.0; =scripts/check-version.mjs= was red on all five and is green now ("every version literal agrees on 1.2.0"). =npm run typecheck= clean and =npm test= 768 of 768 after the change.

** Fixed — a long word in a heading dragged the whole page sideways (2026-09-09)
- *A PHONE COULD SCROLL A DOCUMENT SIDEWAYS, AND THE HEADING DID IT.* =.org-heading= set a display face and a letter-spacing but never said what to do when a single word is wider than the screen, so =overflow-wrap= stayed at its =normal= default: no legal break point inside a word, therefore the word overflows and the document's scroll width grows to match. Measured on a Spanish article at both 320px and 342px — the page scrolled *41px* sideways at both, identically, which is the signature of one fixed-size string rather than a layout that fails to scale. Body prose never reaches this, because its words are small enough to fit at any supported width; only headings are set large enough for an ordinary word to outgrow a phone, which is why the rule lands on =.org-heading= and not on =.org-root=. Verified by the reverse experiment too: forcing =min-width: 0= onto the grid items changed nothing, so this was never the classic grid blow-out it resembles.

** Added — the host decides which enhancements run (2026-09-09)
- *THIRTEEN ENHANCEMENTS, NO WAY TO REFUSE ANY ONE OF THEM.* =boot()= called every initialiser unconditionally, so a host that already owned one of these behaviours got a second copy of it: a site with its own image viewer opened TWO overlays on one click, and a site that did not want a reading-progress bar got one welded to =<body>= regardless. There was no seam to close — the guard flags are set BY the initialisers, so pre-setting one from the host is a race the host usually loses (measured: o2h's lightbox still bound the image and still opened), and every listener is anonymous, so nothing can unbind them afterwards. The runtime now reads =window.O2H_CONFIG= ONCE at boot and skips any feature whose key is =false=; everything else stays on, so a host that never sets it sees no change at all. =window.O2H= additionally exposes the resolved config and the individual initialisers, for a host that would rather compose its own boot order. An inline =<script>= is never deferred, so the host's decision always lands before the runtime exists rather than being a race it has to win.

** Fixed — LaTeX environments were never typeset (2026-09-09)
- *=\begin{equation}= REACHED THE READER AS THE WORDS "\begin{equation}".* The inline scanner matched exactly four delimiter pairs — =$$…$$=, =\[…\]=, =\(…\)= and =$…$= — and an environment is none of them, so the block fell through to the surrounding text rules: the wrapper survived as literal prose, the body was half-converted by the =$= scanner around it, and the page showed =\begin{equation} ∫ … \frac{√{π}}{2} \end{equation}= set as a paragraph. Org writes real mathematics this way far more often than it writes =$$=, and the engine's own fixture corpus had been rendering it broken since the day math landed — nothing in the suite asked whether the output was mathematics or a description of it, because counting construct CLASSES cannot tell the two apart (=.org-math= is emitted either way). A closed list of nineteen environments (=equation=, =align=, =gather=, =multline=, the matrix family, …) is now recognised, in both plain and starred form, and handed to temml WHOLE rather than unwrapped: the environment is the thing that numbers an =equation= and aligns an =align=, so stripping it would throw away the point. An unknown name is deliberately left as text — =\begin{verbatim}= is not mathematics, and guessing would only hand temml something it would refuse.

** Fixed — three more rules that defeated the sheet's own vertical rhythm (2026-09-09)
- *THE FOOTNOTES SECTION SAT IN A 144px BAND WITH A RULE FLOATING IN IT.* =.org-root .org-footnotes { margin-top: 96px }= in =styles.css= is (0,2,0) against the (0,1,0) of the =.org-root > * { margin-block: 0 }= law twenty lines above it — the same specificity trap as the paragraph rule, in the same sheet, for the third time. The grid's 48px row-gap already spaces a top-level block; the margin is gone and row-gap owns it.
- *A DISPLAY EQUATION GREW A VERTICAL SCROLLBAR.* =.org-math-display= declared =overflow-x: auto= to let a long equation scroll sideways, but per CSS Overflow 3 that promotes =overflow-y= from =visible= to =auto= as well. The rendered =<math>= box lands on a fractional height — 60.6px inside a 61px line — and those two stray pixels were enough to lay out a real 6px scrollbar down the right of every display equation, on a box that never overflowed horizontally at all. Both axes are now named.
- *THE READING-PROGRESS BAR READ 100% BEFORE THE READER SCROLLED.* =styles.css= paints the track transparent and only the =<i>= fill accent, which is correct; =kwo.css= then re-declared the TRACK as accent at the same specificity and later in the cascade, so the fill was invisible against it and the element read as a permanent full-width band across the top of the page. The book colours the fill now.
- *AN =<a>= INSIDE =#+BEGIN_EXPORT html= WAS UNSTYLED.* Every link rule in both sheets is written against =.org-link=, which the renderer only puts on links IT emits; a hand-written anchor in an export block passes through verbatim and fell to the browser's default — cyan and underlined, in a document that uses that nowhere else. The bare element joins the book's link rules at (0,1,1), below every classed anchor rule, so the TOC, footnote backrefs, tag links and embed bylines all keep winning and only genuinely unclassed anchors change.

** Fixed — a bar chart sat right of centre inside its own viewBox (2026-09-09)
- *NOTHING IN THE MARKUP WAS MISALIGNED, WHICH IS WHY IT WAS HARD TO SEE.* The =<figure>= was centred in the text column and the =<svg>= filled it edge to edge — but inside the viewBox the gutters were not a pair. =PAD_R= was a flat 12 because that is all a bar needs to avoid touching the edge, while the left gutter is 56, or 84 when there is an axis title, because the tick labels and the rotated title live there. The plot area was therefore inset ~71px on the left and ~10px on the right, and the bars read as pushed right under a caption and a column that were both centred. The right gutter now MIRRORS the left, so the drawing is symmetric at 71/71 and the bars sit 111px from each edge of the text column. It costs plot width — 624 units to 552 with an axis title — and buys a picture whose mass is where the reader expects it, which is the whole job of a picture.

** Fixed — the carousel seam was a teleport with a drift chasing it (2026-09-09)
- *THE WRAP CUT, AND THEN THE SHEET ANIMATED THE CORRECTION.* Moving from the last slide to the first is a deliberate instant move — smooth-scrolling the whole strip back past the reader reads as the carousel losing its place rather than wrapping. But =.org-carousel-strip= also carries =scroll-snap-type: x mandatory= and =scroll-behavior: smooth=, so the snap engine re-settled after the teleport and, obeying the sheet, animated that re-settle: a cut followed by a visible slide. Both are suspended for the frame the jump lands in and restored on the next, so the seam is one clean cut.
- *THE CUT IS NOW DECIDED BY THE WRAP, NOT THE DISTANCE.* =Math.abs(to - from) > 1= meant a TWO-slide strip animated its wrap (the distance is 1) while a three-slide strip cut — the same gesture behaving differently for a reason no reader could see. Asking whether the index went backwards while moving forwards names the seam exactly, at any length. A dot-rail click that crosses more than one slide now cuts too, instead of dragging the whole strip past the reader.
- *THE ACTIVE DOT WALKED THE WHOLE STRIP MID-ANIMATION.* =setActive()= ran up-front, then the rAF-throttled scroll listener recomputed the nearest slide on every frame of the smooth scroll, so the dot lit each slide in turn and snapped back at the end. The destination is pinned for the length of the move and released on a timer, so the rail shows where the strip is going rather than everywhere it passes.

** Fixed — the Style Book overrode the rhythm law it states (2026-09-09)
- *EVERY TOP-LEVEL PARAGRAPH SAT IN 72px OF AIR INSTEAD OF 48.* =templates/styles.css= states the law — "outer block margins are dropped so row-gap owns the vertical rhythm" — and writes =.org-root > *= with =margin-block: 0= at (0,1,0). =templates/style-book/kwo.css= writes =.org-root .org-paragraph= with =margin: 0 0 var(--o2h-space-3)= at (0,2,0), which outranks it, so a paragraph's own 24px compounded with the grid's 48px =row-gap=. THE SCOPE WAS WIDER THAN IT LOOKED: a heading-less document makes every paragraph a direct child of =.org-root=, but a document WITH headings still puts its intro paragraph there too — only paragraphs inside =section.org-section= were spaced correctly, and those genuinely need the margin because no =row-gap= reaches them. So the defect touched every document, and the heading-less case merely made it unmissable. One rule placed directly after the offender, =.org-root > .org-paragraph= with =margin-block: 0=, hands the direct children back to the grid: equal specificity (0,2,0), later source order, direct-child only, so nested rhythm is untouched. Measured in Firefox against a rebuilt bundle — the top-level gap goes 72px to 48px, exactly the declared =row-gap=, while section paragraphs still measure 24px.

* [v1.1.0] — 2026-09-08 :: The Style Book Release

** Fixed — production stability (2026-09-08)
- *THE LOCKFILE FAILS =npm ci= UNDER NPM 10.* Vitest's nested vite@8.1.2 peer-depends on esbuild ^0.27||^0.28; the lock held only tsup's 0.25.11. npm 11 (this machine) tolerated it; npm 10 (setup-node on Node 18/20/22) exits 1 with "Missing: esbuild@0.28.2 from lock file". Every =npm ci= step in =ci.yml= and =publish.yml= runs on Node 20, so both workflows died at step one and a tag would not publish. Regenerated with npm@10.9.9: +27 keys (=esbuild@0.28.2= and 26 =@esbuild/*= platform packages), no existing version changed.
- *=scripts/check-lockfile.mjs= GATES THIS.* Copies =package.json= + =package-lock.json= to a temp dir and runs =npm ci --ignore-scripts --dry-run= under npm@10.9.9. Wired into =precheck.mjs=. Proven red on the old lock, green on the new one. Needs the network for npx.
- *A TITLE THAT SLUGIFIES TO NOTHING WROTE THE PAGE AT THE OUTPUT ROOT, AND THE NEXT BUILD DELETED THE OUTPUT.* =slugify(strict)= keeps ASCII word characters only, so a =#+TITLE= in any non-Latin script — or made of punctuation, an em dash or an emoji — returned =""=. With no =#+DATE= the whole slug was =""=, =resolveInside= resolved it to =--output= itself (the root is "inside" the root, by design), and =index.html= plus every sidecar landed at the top of the output directory. Rename or delete that document and the next build read =""= back out of =.o2h-manifest.json= and ran =rm -rf= on the output root, taking operator files (=CNAME=, =assets/=) with it. Exit code 0 throughout. =generateSlugFromMetadata= now takes the file's stem as a fallback and falls through title-slug, stem-slug, =untitled-<sha1>=, =untitled= — never =""=; and the build refuses an empty route as a named per-document failure.
- *THE PRUNE WAS RECURSIVE AND UNKEYED, SO IT DELETED LIVE PAGES.* =rm -rf= on a stale entry took every CURRENT page nested under its path with it: =docs/guide.org= and =docs/guide/intro.org= build to =docs/guide= and =docs/guide/intro=, so deleting the parent source removed the child's output while the sitemap and manifest went on advertising it. Two corpora sharing one =--output= had the same shape: the second build pruned every page of the first. The manifest now records the =input= it was built from and a mismatch refuses to prune with one stderr line; a stale page has only the six artefacts this engine writes unlinked (=index.html=, =index.vue=, =metadata.json=, =og-metadata.json=, =structured-data.json=, =relations.json=) and its directory removed only if nothing else remains.
- *A FAILING BUILD PRUNED THE PAGE IT HAD JUST FAILED TO REBUILD.* A document that failed never reached =usedPaths=, so the prune read it as stale and deleted its last good output — the exact page a redeploy would have served — and then overwrote the manifest to match. A build with failures now prunes nothing and leaves =.o2h-manifest.json= as it was.
- *DOMPurify WAS SILENTLY DROPPING A QUARTER OF ALL HEADING IDS.* =SANITIZE_DOM= refuses any =id= whose value is already a property of =document= or of a =<form>= — the defence that stops an author overwriting =document.body= with an element, and one worth keeping. The cost was invisible: an Org heading called *Images*, *Links*, *Location*, *Name*, *Body*, *Title* or *Plugins* slugs to exactly such a name, so the =id= never reached the output while the table of contents and every =[[*Heading]]= link went on pointing at it. 140 slug-shaped names collide; this repository's own fixtures hit two of them (=Body= in the corpus, =Images= in the complete template) and no test asserted the id survived. A clobbering anchor now takes a =-section= suffix in =src/parser/slug.ts= — the one function the renderer's =id=, the table of contents and the parser's =[[*Heading]]= resolution all share, so the three cannot disagree — and a =:CUSTOM_ID:=, which bypasses slugification, gets the same check. The control is untouched: =SANITIZE_DOM= stays on.
- *THE CLOBBERING LIST CANNOT DRIFT IN SILENCE.* It is a frozen literal so the parser stays pure and never boots jsdom to slug a heading, and =tests/sanitizer.test.ts= runs DOMPurify's own =value in document || value in formElement= check against a live window and fails on any difference. A jsdom upgrade that adds or removes a property fails the suite rather than quietly un-fixing the anchors.
- *THE DEFAULT SANITIZER WAS EATING COMPONENT PROPS, AND THE TESTS COULD NOT SEE IT.* A component placeholder carried its props as BARE attributes, and DOMPurify strips any bare attribute it does not recognise. Only the ten names with a =data-*= twin survived, so =#+BEGIN_COMPONENT Card :image … :title … :variant … :count … :height …= handed the generated SFC ={title, height}= — two of five — in every build that did not pass =--no-sanitize=. Nothing warned. =tests/components.test.ts= rendered every case with =sanitize:false=, so the suite was blind to it by construction. The =data-props= channel now rides on every placeholder that has props to carry, not only on one with a structured JSON body, and values are coerced from the same escaped text the Vue generator reads off a bare attribute so the two paths cannot disagree about a value's type. The attribute-name allowlist applies to the channel too: a name refused as an attribute (=style=, any =on*=) cannot re-enter as a prop.
- *A FAILED WRITE WAS A WARNING ON STDOUT, AND =--quiet= DELETED IT.* =--quiet= replaces =console.log= with a no-op, and the failures for =routes.js=, a template-asset copy and =createDefaultAsset= all reported through =console.log= and left the exit code at 0. =mkdir out/routes.js= then =org2html build -q= produced ZERO bytes of output and said the build succeeded. All three now report on stderr and set exit 1: THE ENGINE REFERENCES NO ASSET IT DID NOT WRITE, so an asset the head links to and the build failed to produce is a failed build. Font-copy and Style-Book-asset refusals stay warnings, but move to stderr where =--quiet= cannot reach them.
- *"Build complete!" COULD PRINT ON A BUILD THAT EXITED 1.* Asset, font and =routes.js= failures are not document failures and never incremented the failure counter, so the success line printed anyway. The tail now checks the exit code and prints the failure line instead.
- *=--strict= IGNORED AN UNRESOLVED =#+INCLUDE=.* It covered unknown components only, so a document whose include could not be resolved shipped with a hole in it and exit 0 — under the very flag that exists to refuse that. An unresolved =#+INCLUDE= / =#+SETUPFILE= now fails the document under =--strict=, naming the file, and still warns without it.
- *ENGINE WARNINGS NAMED NO DOCUMENT.* =org2html: unknown component "Ghost"= arrived with nothing to grep for in a corpus of hundreds; the lexer, the parser and the SEO resolver were equally anonymous. The CLI is the layer that knows the path, so it stamps it: every warning raised while a document is parsed, rendered or templated is now prefixed with that document.
- *AN UNDEFINED MACRO VANISHED WITHOUT A WORD.* ={{{nosuchmacro(a,b)}}}= expanded to nothing and said nothing, so a byline built from a macro whose =#+SETUPFILE= never loaded simply disappeared. Emacs errors here; this converter still expands to nothing so one typo cannot fail a document, but it now says so once per macro name per document. =parse()= stays pure: it warns, never throws, and has no strict mode of its own.
- *A DOCUMENT OVER 10,000 LINES NOW SAYS SO BEFORE THE MACHINE FINDS OUT.* A measured 40,051-line file peaks at 1.59 GB resident with the highlighter and 0.72 GB without. One stderr line names the size and =--no-highlight=.
- *AN ORG TIMESTAMP REACHED FOUR SIDECARS RAW WHILE THE HEAD PUBLISHED ISO.* =#+DATE: <2026-03-01 Sun>= gave the page's JSON-LD ="datePublished":"2026-03-01"= — and gave =structured-data.json= ="datePublished": "<2026-03-01 Sun>"=, =og-metadata.json= the same for =publishedTime=, =feed.json= for =pubDate= and =sitemap.json= for =lastmod=. ONE HEAD, TWO OUTPUTS: a sidecar may not contradict the head it sits beside, and =<2026-03-01 Sun>= is not a date any crawler parses. All four now emit =dateIso= and omit the field entirely when there is no date. =metadata.json= keeps both =date= and =dateIso= on purpose — it is data for the host, not a crawler surface. The visible byline still reads exactly as the author wrote it, inside =<time datetime="2026-03-01">=, which is what that element is for.
- *sitemap.json's =lastmod= WAS THE WALL CLOCK.* An undated document got =new Date()=, so two builds of identical sources produced different sitemaps and THE BUILD IS DETERMINISTIC quietly stopped being true. An undated document now carries no =lastmod= at all. The integration test that asserted every entry "carries a lastmod" was asserting the defect: a truthy wall-clock value satisfied it. It now checks the ISO shape instead, which a wall-clock timestamp and a raw Org stamp both fail.
- *AN UNTITLED DOCUMENT WAS INDEXED AT ONE ROUTE AND WRITTEN AT ANOTHER.* The corpus pre-pass slugged a header skim while the render pass applied the file-name fallback first, and =titleFromFilename= strips date and ordering prefixes — so =2026-08-21-my-post.org= was indexed at =/2026-08-21-my-post= and written at =/my-post=. The document got no =relations.json= and its neighbours' prev/next pointed at a URL nothing ever wrote. Both passes now run the same file name through the same function.
- *A =#+TITLE= BUILT FROM A MACRO DRIFTED THE SAME WAY — CONFIRMED, NOT ASSUMED.* This was recorded as an untested hypothesis; it reproduces. The pre-pass read the raw ={{{name}}}= because the macro lives in a =#+SETUPFILE= it never opened, so it slugged a route the render pass would never write. The pre-pass now resolves the file layer and expands header macros through =parseHeaderMetadata()= — the keyword scan alone, no body tokenisation, so the index still does not cost a second parse.
- *robots.txt SHIPPED AN UNSUBSTITUTED PLACEHOLDER POINTING AT A FILE THE ENGINE NEVER WRITES.* The built =robots.txt= read =Sitemap: {{baseUrl}}/sitemap.xml= literally: the template is copied, never templated, and the engine emits =sitemap.json=, not =sitemap.xml=. Every crawler that read it was sent to a 404 with a =\{\{= in the URL. The =Sitemap:= line is gone from the template and from the built-in default; =User-agent: *= and =Allow: /= stay. A host that composes a real =sitemap.xml= owns =robots.txt= through =--template-dir=.
- *manifest.json SHIPPED A BRAND NOBODY CHOSE.* It was copied verbatim, so every install published =theme_color: "#FF5114"= and =name: "Blog"= beside a head resolving =#f9cd26= — the same drift already fixed for =og-metadata.json=, in the one file an installed PWA reads. It is now composed like =styles.css=: the theme colour comes from the resolved Style Book token, and =name= / =short_name= from =#+SITE_NAME= when the corpus declares one.
- *THE GENERATED VUE COMPONENT SHIPPED THE WORDS "Invalid Date" TO READERS.* The SFC's =formattedDate= computed called =new Date(metadata.date).toLocaleDateString()= inside a =try/catch=. For an Org timestamp that Date is invalid — and =toLocaleDateString()= on an invalid Date RETURNS the string "Invalid Date" rather than throwing, so the =catch= was dead code and those two words rendered on the page. For a plain ISO date the same call is UTC midnight, so every reader west of UTC saw the day BEFORE the one the author wrote (=TZ=America/Bogota= printed =2/28/2026= for =2026-03-01=). =src/cli/utils.ts= goes to real trouble to avoid exactly this at build time; the browser now gets the same answer. The computed builds a local Date from ISO components, preferring =dateIso=, and falls back to the authored text only when there is no ISO date to read.
- *UNCLOSED INLINE OPENERS MADE PARSING QUADRATIC.* =parseInlineMarkup= met an opener, scanned forward for its closer, failed, and then did the same thing again at the next opener — so a paragraph of unclosed openers cost time proportional to its length SQUARED. Measured on this machine before the fix: emphasis, =\[= and =$= all grew about 4x per doubling of input, and a 161 KB paragraph of =*a *b *c …= took 21 s. Nothing hung, nothing warned, and a document like that is an accident rather than an attack — a paste, a stray asterisk, a price list. Each scanner now remembers the position from which its closer was already proven absent. A scan that failed from one point cannot succeed from a later one, because every scanner runs forward to the end of the text and a position's validity as a closer never depends on where the scan began — so the only work removed is work that was going to return nothing. The same 161 KB paragraph now parses in 54 ms, and the built corpus is byte-for-byte identical to the build before the change.
- *=npm run scan:perf= MEASURES THIS, AND CAN FAIL.* =scripts/scan-perf.mjs= parses nine unclosed-opener patterns at n, 2n and 4n and reports the growth ratio per doubling. It measures GROWTH rather than absolute speed, so it says something on any machine, but it is a wall-clock probe and is deliberately NOT part of the test suite or =precheck=: a timing assertion on shared CI is a gate that fails for reasons that have nothing to do with the code. It was run on the unpatched tree first and exited 1 with three patterns flagged SUPER-LINEAR; it exits 0 now.

** Changed — production stability (2026-09-08)
- *THE SANITIZER NOW SCOPES INLINE CSS BY DECLARATION, NOT ONLY BY TAG.* =[D-07]= restricted the =style= ATTRIBUTE to =<pre>=, =<code>= and =<span>= so the highlighter's colours survive, but on those three it then allowed any CSS at all — enough to blank a page with =position:fixed;inset:0=, or to report what a reader is looking at with =background:url(https://…)=. CSS is not script, so none of it was caught by the script defences. Declarations are now checked against what the engine itself emits: colours (=var(--shiki-…)= for css-variable themes, hex for the others), the three text-style keywords a theme can set, and plain geometry. No =url(=, no =expression(=, no =position=, and nothing that can move an element or fetch a resource. An unrecognised declaration removes the whole attribute rather than one line of it — a half-applied style is a guess, and this fails closed.
- *THE =<style>= ELEMENT IS REFUSED IN DOCUMENT BODIES.* An =#+BEGIN_EXPORT html= block could ship =<style>body{display:none}</style>= and restyle or blank the entire page. The engine never emits =<style>= into a body — the head's blocks are assembled by =applyTemplate= and never pass through the sanitizer — so this costs the engine nothing and costs an author only a technique that was never safe. =--css-append= and =--no-sanitize= remain for authors who want it.
- *THE ALLOWLIST IS WIDER THAN THE ONE FIRST SKETCHED, AND FOR A MEASURED REASON.* =width= and =height= are permitted because the engine's own Style Book showcase draws its spacing scale with =<span style="width:4px;height:4px">= — geometry that cannot overlay, position or fetch anything. The =background= shorthand is permitted because the VALUE gate, not the property name, is what stops exfiltration: =background: #000= is a colour, while =background: url(https://…)= matches none of the permitted value shapes and takes the whole attribute with it. With those two, the built corpus is byte-for-byte identical to the build before this change.
- *=engines.node= IS NOW =>=18.13.0=, WHICH IS THE FLOOR THE TREE ALREADY ENFORCED.* =temml= declares =>=18.13.0=, so =npm install --engine-strict= has always refused Node 18.0–18.12 while =package.json= went on claiming 18.0.0. Measured on real binaries: an =--engine-strict= install of the tarball exits 1 with =EBADENGINE= under 18.12.1 and exits 0 under 18.13.0. This narrows the declared range ON PURPOSE and says so out loud — nothing that installed before stops installing, because nothing below 18.13 ever did.
- *=scripts/smoke-install.mjs= NOW INSTALLS WITH =--engine-strict=.* The install smoke ran without it, so a dependency raising its floor above ours would have been discovered by a consumer rather than by CI. It is now loud on the 18/20/22 matrix.
- *=slugify= IS PINNED EXACTLY AT 1.6.9, WHICH IS A CEILING AS WELL AS A FLOOR, AND THAT IS DELIBERATE.* A document's route is =slugify(title, { lower: true, strict: true })=, so the dependency's transliteration table is part of this package's public surface: a charmap change renames pages, breaks canonicals and breaks inbound links. An exact pin makes any future change a decision rather than an accident. =tests/slug-golden.test.ts= holds thirty hostile titles with literal expected slugs so the pin means something — proven able to fail by flipping one literal. Across the 1.6.6 to 1.6.9 bump, zero of the thirty changed.
- *AN AUTHORED IFRAME NO LONGER CHOOSES ITS OWN PERMISSIONS.* The =src= gate was already tight — the nocookie host and an eleven-character id — but =allow= passed through untouched, so an export block could ship =allow="camera; microphone"= inside a frame a reader takes for a video. =allow= is now PINNED to what a video embed needs (=accelerometer=, =clipboard-write=, =encrypted-media=, =gyroscope=, =picture-in-picture=) and replaces whatever the author wrote rather than merging with it, so there is no token list to get wrong.
- *FORM ELEMENTS ARE REFUSED IN A DOCUMENT BODY.* DOMPurify permits them by default, so an export block could post a password field to a third party from a page that reads as an article. =form=, =select= and =textarea= are forbidden outright. =button= and =input= are NOT, because the engine emits both — the code block's copy control and tab headers are buttons, and an Org task item (=- [X] done=) renders a disabled checkbox carrying its accessible label. =input= is instead narrowed to =checkbox= and =radio=, so a text, email or password field from an author's export block does not survive while a task list keeps its checkboxes.

Setting it never did anything, so no working behaviour changes — but a documented option that does nothing is the same silent wrong answer as everything else in this release.

Measured here: a short document is ~203 KB inlined and ~3.9 KB linked beside one shared ~200 KB =styles.css=. The same construct one line lower worked, which is what made it hard to see. The header scan now stops at =#+BEGIN= / =#+END=, the way it already stopped at =#+CAPTION= and =#+NAME=.

The counter is carried per base now — 55 ms for the same document, and the ids are unchanged (=same=, =same-2=, =same-3=). The =while= guard stays, so an explicit =:CUSTOM_ID:= that collides with the counter is still stepped over.

On stderr, so =--quiet= cannot swallow a diagnostic somebody asked for by name.

A bare array is still read as the legacy shape; because its input is unknown, the first build after the upgrade warns and prunes nothing, then writes the new shape. One skipped prune, once.

Those anchors were already dead — the id was not in the document — so nothing that worked stops working, but a hand-written deep link to one of them needs the suffix.   padding box equal to the border box. Measured after: padding box *32x32*, and every avatar now

  =<blockquote>= needs =margin: X 0= to drop its UA inline margin) reset the negative
  inline margin they depend on. A nested full-bleed figure kept its =100vw= width but
  lost its pull, pushing the whole page into a horizontal scroll. The breakout block
  moved to the end of the sheet under a "must stay last" note.
- *The default book now obeys its own laws end to end* (=templates/style-book/*=,
  =templates/styles.css=). Measured on the style-audit page and re-measured after:
  zero non-hairline strokes (every stroke is 1px and reads by alpha from the Book's
  =0.08 / 0.12 / 0.2 / 0.35 / 1= ladder), zero border radii outside the law's named
  tooltip exception, zero content below the 14px legibility floor, and no
  horizontal scroll. What changed to get there: links are ink with an underline and
  take the accent only on hover (they were accent-coloured); a rule is 1px, not a
  2px accent bar; lists are rows with square markers and hairline seams instead of
  browser bullets, with the ordered list numbering through =::marker= so =[@n]=
  still sets the ordinal; a code block is a black well with ONE accent square
  instead of three macOS traffic lights, and its highlighter now paints the Book's
  six token roles (keyword / string / number / comment / function / punctuation)
  rather than a saturated github-dark palette; tables are hairline grids with a
  mono head instead of an inverted ink plate; callouts are bands with a 4px state
  stripe; controls never fill (the accent is a frame and a label, hover a 12%
  tint); the spacing scale moved onto the 8px grid; and every white inverted
  component plate became a dark surface.
- *Media reserves its space* (=kwo.css= §8): a figure is a hairline frame with an
  inset, an image paints the grain plate under it and locks the book's ratio when
  it carries no dimensions, a =<video>= sits in the same well with the same ratio,
  and a caption is a mono line over a hairline rather than centred prose. This is
  the [A2] standard, and it is also what stops a document reflowing as assets land.
- *Stroke weight, radius and the state washes are TOKENS* (=templates/styles.css=).
  The shared sheet hardcoded =2px= / =3px= / =4px= borders, a =10px= radius and two
  =rgba()= diff tints, so no book could rule them. They now read =--o2h-rule=,
  =--o2h-stripe=, =--o2h-rail=, =--o2h-stripe-thin=, =--o2h-radius= and the wash
  tokens; the preserved O2H book declares each at the value the sheet used to
  hardcode, so it renders exactly as before.
- *Media breakouts survive any later rule* (=templates/styles.css=): raising the
  breakout selectors to =(0,3,0)= by repeating the class. Source order alone was not
  enough — the book layer loads after the shared sheet, and a single =margin: X 0=
  on =.org-figure= there was enough to reset the inline margin again and put the page
  back into a horizontal scroll.
- *A description item survives a continuation line* (=parser.ts=parseListItem=):
  the =term :: definition= match used =.= for the definition, which stops at a
  newline, so a wrapped description item silently rendered as a plain bullet with a
  literal =::= in it. Surfaced by the list-continuation fix earlier the same day —
  the two land together. =tests/affiliated-stacking.test.ts=.
- *Six corrections from the owner's side-by-side review of the reference pages*
  (=templates/style-book/*=, =templates/o2h.js=, =src/plugins/shortcode.ts=,
  =src/renderer/html-renderer.ts=, =examples/site/src/styles/site.css=):
  1. *An embed names its platform.* =\{\{< youtube >\}\}= now emits the [A2] source
     badge — a brand mark in the platform's own colour, the platform name, and the
     channel when =channel="…"= names one — on a blurred near-black plate behind a
     hairline in the frame's bottom-left, aria-hidden because the iframe already
     carries the accessible name.
  2. *The carousel follows the reference carousel.* It was a scrolling shelf of
     tiles; the reference (=now-projects-section.vue=) is ONE 16:9 frame with an
     accent hairline showing one image at a time, navigated by DOTS. The runtime
     now builds a =prev · dots · next= rail (rAF-throttled active tracking), every
     tile is exactly one frame wide and snaps to centre, the nav buttons are 2.5rem
     accent squares that lift 2px on hover, and the strip's scrollbar is hidden
     because the dots are the affordance.
  3. *A status flag is ONE colour.* The TODO dot was pinned to the accent, so a
     green DONE carried a yellow dot — two colours encoding one state. The dot is
     =currentColor= now.
  4. *The body is the reference body.* fs-400 (18px) at a 68ch column was a
     different page from the one the shell renders: the reference document sheet is
     fs-300 (15px) at 58rem, "89 chars at 696px". The book now renders exactly that,
     and the showcase stopped capping =.org-root= at the measure a second time —
     that double-cap was subtracting the engine's own gutters and had the reading
     column at 616px.
  5. *=<mark>= is a selection.* An author's highlight now wears the same two colours
     as =::selection=, from the same tokens, so a marked run and a dragged-over run
     are indistinguishable.
  6. *Priority is a rank.* =[#A]= takes the stop colour, a wash and bold; =[#B]= the
     hold colour; =[#C]= a quiet hairline — colour, weight and fill stepping together
     so the order survives greyscale ([A4] never colour alone). The renderer mirrors
     the letter to =data-priority= so a book can rank the chip without parsing text.
     Every headline flag (TODO / DONE / priority / tag / cookie / timestamp / cite)
     now shares ONE height and ONE padding, so a row of them cannot read ragged.
- *The owner's ten calls on the default book, applied* (proposals page, 2026-08-24).
  Eight accepted, two declined — and =tests/book-decisions.test.ts= locks BOTH, so a later
  "improvement" cannot quietly re-open a decision that was made:
  · *D-01* a document page paints no ambient HUD marks. [A1]'s colour law names HUD
    decoration directly, and this was the one rule in the book contradicting a source it
    otherwise follows line by line. The hooks stay for a host that wants them.
  · *D-02* the masthead starts flush with the prose. The negative pull outside the reading
    column read as a misaligned page; both reference documents share one left edge.
  · *D-03 DECLINED* — display math keeps its raw form and its delimiters.
  · *D-04* a CLOCK line renders as the measurement it is: a label, its two stamps and the
    duration, each its own element. An unrecognised shape still prints verbatim.
  · *D-05* the video embed is a facade (see Added).
  · *D-06* the tick rule carries end caps. Alpha alone left two named variants rendering
    the same 1px line — still hairlines, the weight coming from two more marks.
  · *D-07* the ribbon decoration is a hairline mark, not a solid accent slab — it was the
    "big flat fill" [A4] small-things-build-big rejects, and the largest unbroken block of
    accent in the book.
  · *D-08 DECLINED* — the contents stays a flat indent.
  · *D-09* =.org-video= / =.org-audio= hooks (see Added).
  · *D-10* the long-form entity names Emacs ships (=\rightarrow=, =\dots=, the arrow
    family, quotes, =middot=, =sect=, =para=) expand instead of printing the backslash word.
- *An off-site link carries the external MARK, painted by currentColor* ([A2]
  =_theme.scss .icon-mask--external=). It was a muted "↗" character with a colour of its
  own; masked, it travels with the link's state — ink at rest, accent on hover — and reads
  as a mark rather than a stray arrow in the sentence. The character stays in the markup as
  the no-book fallback.
- *The checkbox marks are DRAWN, and read from the item's own state* — two bugs at once.
  The 6px list-marker square was painting INSIDE the 14px box, because
  =.org-root .org-ul > li::before= is specificity (0,2,2) and the suppressing rule was
  (0,2,1): equal-looking selectors, and the marker won. And the tick was a =✓= character,
  which sits wherever its font decides — cramped and off-centre in a 14px box. The tick is
  now two borders rotated 45°, on the pixel at any size. Org's PARTIAL state =[-]= also had
  NO rendering at all (=indeterminate= is JS-only, so keying off =:checked= made a half-done
  item identical to an untouched one); the book reads =data-checkbox= from the item, so
  partial has its own bar and a done item's text steps back one tone.
- *The embed's frame ratio moved to =.org-embed-stage=* — the source line is a sibling
  under the frame now rather than an overlay on it, so the outer =.org-embed= is a stack
  and the stage owns the well, the plate and the 16:9 box.
- *The inline task stops spending an off-palette hue, and its tag stops colliding with
  the frame* (=kwo.css=). It wore a magenta rail (=--o2h-working=) — the one colour on the
  page that appears nowhere else and encodes nothing by itself, so a reader saw two colours
  for one state. The keyword chip already says which state the task is in, so the box is
  neutral now and the token stays for a host that has a live/in-flight state to encode. The
  heading is also a flex ROW (flags · title · tags right), because laid out inline the tag
  wrapped onto a second line and overlapped the box edge.
- *og:site_name named the ARTICLE, not the site* (=templates/default.html=). Every page
  told a crawler it belonged to a differently-named site — a defect that never breaks a
  build and does real damage to how a domain is understood. It now comes from =#+SITE_NAME=
  and is omitted when the document does not name one.
- *article:tag carried every term comma-joined into ONE meta*, which reads as a single long
  tag rather than several. The property is explicitly repeatable, and repeating it is how
  the terms are actually seen.
- *Structured data no longer publishes URLs a crawler cannot resolve.* =url= and
  =mainEntityOfPage= are identities, so they are emitted only when the canonical is
  ABSOLUTE (=--base-url=); a =BreadcrumbList= only when every crumb resolves. A relative
  =@id= names nothing, and publishing one looks like an answer. The build also never used
  its own =--base-url= for the canonical it stamps — it does now.
- *The JSON-LD gained the fields a blog post is judged on:* =dateModified=,
  =articleSection=, =inLanguage=, =publisher=, =mainEntityOfPage=, and =isPartOf= for a post
  in a series. The head gained =og:locale=, =og:site_name=, =og:image:alt= (only with an
  image), =article:section=, =article:modified_time= and =rel=prev= / =rel=next=.
- *rel=prev / rel=next reached only the STATIC head* (=src/cli/vue-generator.ts=). A site
  rendering the =.vue= shipped the navigation on the page while its head said nothing about
  the sequence — the exact drift the shared =seo.ts= exists to prevent ("one head, two
  outputs"). Both links are emitted from the same computed relations now, and
  =tests/seo-blog.test.ts= asserts the Vue head carries them.
- *The JSON-LD never reached a Vue-rendered page at all* (=src/cli/vue-generator.ts=). The
  head entry used =children=, the Unhead v1 spelling; under =@unhead= v2 an unknown key is
  rendered as an ATTRIBUTE, so every page built from the =.vue= shipped
  =<script type="application/ld+json" children="{…}"></script>= — a tag with an EMPTY body.
  The structured data was in the markup and invisible to every consumer of it. It is
  =innerHTML= now. This is the worst shape a half-answer can take, because it also passed
  every guard: the unit test and the showcase smoke both asked whether the string
  "application/ld+json" appeared somewhere, and it did — naming a tag with nothing in it.
  Both now PARSE the script body and assert the =BlogPosting= node arrived.
- *og:site_name named the ARTICLE in the Vue head too*, months after the static template was
  fixed (=src/cli/vue-generator.ts=). The static side guards with ={{#if siteName}}=; this
  path pushed =seo.title= unconditionally, so a host rendering the =.vue= still told crawlers
  its pages belonged to as many differently-named sites as it had posts. It now reads
  =seo.siteName= and is omitted when the document names no site.
- *=og-metadata.json= reported the article title as =siteName=, and re-invented its own
  =themeColor=* (=src/cli/commands/build.ts=). A host building its head from the sidecar
  therefore reintroduced the exact defect the head had already fixed, and a swapped style
  book recoloured the head while leaving this sidecar on the old brand's =#0066cc=. Both
  fields now come from =resolveSeo()= — one resolver for both outputs, so the sidecar
  cannot drift from the head.
